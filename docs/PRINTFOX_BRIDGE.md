# PrintFox 圖庫與生圖整合

操作入口：`http://127.0.0.1:8790/admin/recipes/print`。

## 操作順序

1. 展開「AI 圖庫與生圖 · PrintFox」，確認服務網址是 `http://100.99.216.78:8101`。由操作人員自行輸入既有 PrintFox Token，按「連接 PrintFox」。Token 不需交給 Codex，也不需貼在聊天或文件中。
2. 搜尋已有設計並按「匯入原圖」；或展開「輸入描述，產生新圖」，選擇引擎、比例與 1–4 張，按「送出一次生圖」。任務完成後更新圖庫並匯入喜歡的原圖。
3. 在下方選擇商品與印刷面，從「原稿」下拉清單選剛匯入的圖片。匯入不會清掉尚未儲存的商品設定，也不會替換已選好的門片圖稿。
4. 圖片需填入旋轉後的完整印刷尺寸（毫米）與出血。系統會核對長寬比及最低解析度；像素尺寸或檔案中的 DPI 標籤不能證明實際刀模尺寸。儲存後按「生成 3D 套圖」及「產生校稿下載包」。
5. 印刷人員核對實測尺寸、順序方向、出血與治具、材質色彩打樣、RIP 100% 比例後，才產生正式尺寸的下載包。下載與確認不會啟動機台。

## 三個系統的角色

| 系統 | 本輪角色 |
| --- | --- |
| PrintFox（8101） | 既有設計圖庫與單次 AI 生圖；支援既有 ComfyUI / grok imagine 引擎 |
| Fox3D 商品工作台（8790） | 匯入原圖、保留來源與雜湊、毫米尺寸核對、3D 套圖、校稿與人工確認 |
| 現有 Illustrator / NetFox Print / RIP | 保留現場排版及列印操作，尚未自動建立正式工單或送入 UV 熱資料夾 |

這次程式位於 Fox3D repo。PrintFox 既有 `E:\projects\printfox`、Linux 服務及未提交的前端修改均未更動。

## 連線與異常處理

- Token 只送往畫面顯示的管理員設定來源，放在本機服務記憶體中的一小時有效 session；瀏覽器使用 HttpOnly / SameSite Strict cookie。Token 不寫入工作紀錄或 localStorage。服務重啟後需重新連線。
- 管理員可以在所用 data root 下建立 `printfox-connection.json`，只填 `{"baseUrl":"http://host:port"}`。此檔不放 Token。UI 不接受臨時網址，避免把 Token 送往其他位置。
- 「中斷連線」會清除該連線，但不會取消已送出的生圖；重新連線後可管理工作台自己的任務。
- 「送出結果待核對」表示遠端可能已收到。按「更新狀態」查核，不要換瀏覽器重複送出。後端會以已落盤的請求編號對照遠端，不會自動重送不明的 POST。遠端最近 500 筆內找不到時仍保留待核對，由人員確認。
- 每次最多 4 張，沒有連續生圖。只取消本工作區建立、且內容吻合的 generate 任務，不操作 PrintFox 的其他任務或正式印刷。
- 在線工作機數是登入後的 PrintFox 回報；服務健康檢查或未登入的 0 不代表工作機已驗收。選擇雲端引擎會使用既有供應商服務；本輪沒有執行真實 AI 供應商生圖。

## 印刷準確度邊界

PrintFox 原圖以原始 bytes 匯入並保留來源 design ID、generation metadata 與 SHA-256。圖稿與商品尺寸不會自動視為已實測。AI 原始輸出（例如 1216×832）可能不足以印製大型門片，也可能與刀模比例不同；需準備符合刀模的裁切／解析度後再匯入。3D 櫃身深度、板厚與間隙仍可能是示意設定。

使用者提供的 Illustrator JSX 會依原生 AI 路徑位置放置 JPG，並未縮放圖片。現有刀模的部分 PDF 頁面雖顯示 2500×1300 mm，但尚未由 Illustrator 核實槽位與治具原點，不能據此宣稱套圖已達現場印刷精度。本輪不執行或改寫 JSX、不自動套入刀模、不傳送實體機台指令。
